Theme

Design Principles

  1. Level colors are the only semantic color source. The text colors of alert/error/warn/info/debug/trace (--c-*-text) are the "root colors" of the whole system. Every row state — hover, marked (click-selected), bookmarked — derives from the owning level's root color instead of introducing fixed colors. An ERROR row "looks red" in any state; the semantics never get lost.
  2. States differ by opacity, not hue. Different opacities of the same level color encode state intensity: hover ≈ 10%, marked ≈ 14% (plus a left bar), bookmarked ≈ 8% (plus an icon). Higher opacity = deeper user involvement. Hues stay unified and the hierarchy stays legible.
  3. Icons carry state identification; color does not. Bookmarked rows use the ★ icon, marked rows use a left color bar + selection icon. Distinguishing "saved by me" from "clicked by me" is a one-glance icon read, not a guess between two similar cyans.
  4. No hardcoded colors. Today is-copied (rgba(24,95,165)), is-highlighted (rgba(255,220,0)) and is-marked (rgba(100,210,255)) are hardcoded and ignore the theme. The new system uniformly uses color-mix(in srgb, var(--lv-*), var(--bg)), adapting to light/dark automatically.

3 Before / after

Core problems of the current implementation: marked/bookmarked use a fixed cyan that loses level semantics; hover is overridden when states stack.

Current (v0.6)problems

  • hover varies per level via --c-*-bg ✓ meaningful
  • but marked uses the fixed cyan rgba(100,210,255,0.3) ✗
  • bookmarked uses the same-family cyan rgba(100,210,255,0.15) ✗
  • → a selected ERROR row turns cyan; the "error feel" vanishes
  • → marked and bookmarked are both cyan and hard to tell apart
  • → is-bookmarked is last in the CSS and covers hover, so bookmarked rows give no hover feedback
  • → --c-marked-bg is never defined and always falls back
  • → copied (blue) / highlighted (yellow) are hardcoded and theme-blind

Proposed (v0.7)solved

  • every state derives from the level root color via color-mix(lv-*, %, bg)
  • → an ERROR row stays red in every state; semantics preserved
  • marked 14% + left color bar; bookmarked 8% + ★ icon
  • → states are told apart by opacity + icons, not by two similar colors
  • hover uses the compound selector .is-bookmarked:hover to stack and deepen; feedback is never lost
  • uniform color-mix: themes adapt automatically, zero hardcoding
  • jump highlight becomes a level-root pulse that fits the family

Note: color-mix() is supported by 96%+ of browsers (since 2024) — Safari 16.2+/Chrome 111+/Firefox 113+. The project has no legacy-browser requirement, so it can be used directly. A CSS-variable precompute (--lv-cur) + rgba fallback is also viable.

5 Search chip palette

Keyword chips and the in-line <mark> highlights share one palette. Today there are 5 hardcoded rgba rainbow colors (yellow/cyan/magenta/green/orange), unrelated to the level families and theme-blind. Proposed: HSL hue separation keeps multiple keywords distinguishable; per-theme opacity tuning keeps them readable.

Before / after

Current (v0.6)problems

  • 5 hardcoded rgba() values: yellow/cyan/magenta/green/orange
  • colors live in the highlightColors array in App.vue, not CSS variables
  • undersaturated on dark theme; highlights look grayish
  • completely detached from the level families
  • chips and <mark> use separate opacity sets, inconsistent

Proposed (v0.7)solved

  • HSL as variables: --kw-1 ~ --kw-5 with fixed hue values
  • each theme tunes lightness/saturation — brighter on dark backgrounds
  • chips and <mark> share the same --kw-*; visually unified
  • opacity is rule-based (chip 14% / mark 30%), single source of truth
  • hues spread evenly on the color wheel (43°/200°/280°/150°/20°); multiple keywords stay distinguishable

6 App frame colors

The background hierarchy of globalbar / statusbar / sidebar follows the recessed-sidebar scheme: sidebar deepest (--bg-2), globalbar slightly recessed (text 3%) to back the tabs, main area brightest (--bg). Hover the sidebar file items to see their hover state; hover the tabs to see hover/active.
